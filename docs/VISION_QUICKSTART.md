# Дуо через API и сбор кадров

Во время фарма сохраняются исходные кадры без YOLO и SAM. Сам Pilot продолжает
использовать свой CV/OCR для фарма. С `--label-after` проверка имён и SAM запускаются
после подтверждённой остановки фарма. Старый `grab_pic_dataset.py` здесь не используется.

## Подготовка

- Два персонажа уже на споте, окна открыты и доступны для переключения.
- Нужны настроенные профили окон: каталог с `farmer/farm-bars.json` и
  `farmer/party.json`. Пример ниже использует существующий профиль обычного дуо.
- Закрой управляющий GUI HID Pilot: API использует тот же Pico и hard-stop `\`.
  EXE пересобирать не нужно, запуск идёт из исходников.
- Для `--camera` нужна прошивка **HID_PILOT_V7**. Со старой версией запускай без этого флага:
  плата запрещает движение с зажатой ПКМ. Проверка API останавливает несовместимый
  запуск до попытки поворота.
- Проверь `player_name` и нормализованные ROI в `config/vision-video-lu4.json`.
  Live API уже обрезает кадр до клиентской области МА; видеопараметр `crop`
  при live-сборе не применяется. Окна не перемещай и не меняй их размер во время сессии.

## Первый терминал: API

PowerShell из корня репозитория:

```powershell
Set-Location 'C:\Users\blm\Documents\GIT\l2_agent'
.\.venv\Scripts\python.exe scripts/start_pilot_api.py `
  --scripts agent_scripts/duo `
  --profiles hid_pilot/extensions/scripts/farmer-healer_SINGL.duo `
  --farmer-title 'LU4 - Sangry' `
  --support-title 'LU4 - DaizyGreen' `
  --pico-port COM4 `
  --api-file artifacts/pilot-api.json
```

Замени точные заголовки окон, COM-порт и каталог профилей на свои. `--profiles`
указывает на каталог, содержащий `farmer`. Профили не копируются автоматически;
для трёх вариантов API использует явно выбранную текущую калибровку.

API слушает только `127.0.0.1` на автоматически выбранном порту. Файл
`artifacts/pilot-api.json` содержит адрес и секретный токен: не публикуй его.
Если после аварийного выхода остался старый файл, укажи новый путь `--api-file`
в обоих терминалах. Готовность API ещё не запускает фарм.

## Второй терминал: фарм и сбор

```powershell
.\.venv\Scripts\python.exe scripts/run_vision_farm.py `
  --api-file artifacts/pilot-api.json `
  --script farmer-healer_SINGL.duo `
  --output farm `
  --camera --label-after
```

Доступные значения `--script`:

- `farmer-healer.duo`;
- `farmer-healer_SINGL.duo`;
- `farmer-healer_wAOE.duo`.

Это API-форки из `agent_scripts/duo`; исходные сценарии сохранены. Запрет
самостоятельных движений мыши применяет API-адаптер. Открытие копии в обычном GUI
само по себе эту политику не включает. Клавиатурное управление и клики сохранены.

После запуска дай Pilot переключаться между МА и саппортом. Кадры снимаются,
только когда активно окно МА. Саппорт в датасет не попадает.

- `--camera` включает экспериментальный поиск выбранной цели короткими поворотами
  с ПКМ. Если маркеры уже видны, поворота нет. Без флага камера не управляется.
- `--label-after` после STOP запускает проверку имён и SAM в отдельном окружении.
  Нужны уже подготовленные `.venv-train` и `models/sam2.1_t.pt`.

Остановка: `Ctrl+C` во втором терминале или hard-stop `\`. Сборщик останавливает
собственную сессию фарма и при достижении лимита. В конфиге live-сбора: 2 часа,
без лимита числа кадров (`max_samples: null`), 1024 MB, обработка до 2 кадров/с.
Для более долгого сбора увеличь `duration_seconds` и `max_output_mb` в конфиге
до запуска. Числовое значение `max_samples` включает ограничение числа кадров.

При `--label-after` ошибка сбора не отменяет предразметку уже сохранённых кадров,
если STOP подтверждён. `incomplete.json` и исходная ошибка сохраняются; код выхода
остаётся ненулевым. Без подтверждённой остановки разметка не запускается.
Офлайн-скрипты проверки имён и SAM также принимают такой `incomplete.json`.

При потере heartbeat на 5 секунд API останавливает фарм. Сборщик ждёт завершения
worker и освобождения HID; при ошибке или неподтверждённом STOP пишет
`incomplete.json` и не запускает авторазметку. После сбора API остаётся доступен;
закрой его через `Ctrl+C` в первом терминале. Каждый новый сбор требует нового
каталога: передавай в `--output` базовое имя, например `farm`.
По умолчанию сборы сохраняются в `artifacts/farm_samples`; `--output` можно опустить.
Перенесённые туда предыдущие сборы учитываются при выборе следующего номера.
Номер добавляется автоматически: `farm-01`, `farm-02` и далее после наибольшего
существующего номера. Неудачные сборы и каталоги `-names`/`-labels` учитываются;
предыдущие результаты сохраняются. Выбранный путь выводится в журнале.

## Что сохраняется

- `samples/*/image.png` — исходный кадр МА;
- `sample.json` — статус `unlabeled`, session/epoch, маркеры и контекст цели;
- `observations.jsonl` — наблюдения и запросы поворота камеры;
- `review.html`, `report.json` — просмотр и итог сбора;
- после `--label-after`: соседние каталоги `farm-01-names` и `farm-01-labels`.

Маркеры и имя из Pilot не считаются рамкой тела. SAM создаёт предразметку,
требующую проверки; автоматического допуска в обучающий датасет пока нет.

## Ограничения камеры

Камера ищет цель только влево, с HID-смещением ×20: 6 → 120 единиц на импульс.
После импульса снимается свежий кадр. Клиенту даётся 25 мс на обработку ПКМ перед MOVE.
Появление маркеров прекращает повороты. Полный оборот оценивается по возврату
исходного вида сцены (ORB, без HUD и центральных персонажей); это визуальная
эвристика, а не точный датчик угла. При движении персонажа или бедной текстуре
возврат может не распознаться. Резервный предел — 32 импульса и 20 секунд
после команды атаки МА. Каждый следующий поворот требует свежего кадра. Камера
доступна лишь при свежем положительном HP цели без критического состояния,
в активном окне МА, без паузы/STOP; ввод сериализован с командами фарма.
Тип `unknown` допускается только для поиска камерой после команды атаки;
известные игроки/NPC исключены. Это не разрешение атаковать неизвестную цель.
Камера ждёт освобождения ввода до 0,2 с; отказ не расходует локальный бюджет
направлений. Причины пропусков, попытки и выполненные повороты записываются
в журнал и `observations.jsonl`. В отчёте `camera_attempts` — запросы,
`camera_requests` — успешно завершённые повороты.

Это **поиск цели по маркерам, а не точный разворот за спину персонажа**.
Направление бега пока не определяется, наклон камеры автоматически не меняется.
Команда атаки не доказывает движение: поиск может происходить и в начале боя.
Если цель не найдена до возврата исходного вида или достижения предела, фарм продолжается без дальнейших поворотов для
этого выбора цели. Сила поворота ещё требует калибровки на живом клиенте.

## Обновление Pico для камеры

Останови API и другие управляющие экземпляры. Запусти GUI из текущих исходников,
поскольку старый EXE содержит прежнюю прошивку:

```powershell
Push-Location hid_pilot
..\.venv\Scripts\python.exe -m hid_pilot
Pop-Location
```

В обслуживании Pico выбери CIRCUITPY и «Установить / обновить HID Pilot», затем
безопасно извлеки носитель, переподключи USB без BOOTSEL и выполни проверку.
Ожидается HELLO `HID_PILOT_V6`, STATUS `DISARMED`. Полный сброс не требуется.
[Подробная инструкция](../hid_pilot/README.md). Закрой GUI перед запуском API.
На плате пользователя сначала установлена V6 (2026-11-03).
Резервная копия: `artifacts/pico-before-v6/20261103-003331-aa5c6817`.

Обновление того же дня: установлен V7 для ускорения ×20, проверены файлы/HELLO/STATUS.
Резервная копия V6: `artifacts/pico-before-v7/20261103-004051-b4b8b1ab`.
Быстрый поворот проверен в клиенте; отчёт `artifacts/camera-v7-smoke/result.json`.

## Ошибка активации окна при старте

Если Windows отклоняет `SetForegroundWindow` при запуске из терминала, API
использует существующий изолированный helper Pilot: `foreground`, затем
`attached_focus`, затем `task_switch`, с timeout и проверкой фокуса.
Это происходит до подключения Pico. Отказ helper завершает сессию без ввода.
Первичная причина и путь `incomplete.json` выводятся в ошибке сборщика.

После обновления исходников перезапусти API в первом терминале: работающий процесс
не подхватит изменения автоматически. Для повторного сбора оставляй прежнее
`--output farm`: следующий номер будет выбран автоматически.
Неудачный предыдущий каталог сохраняется для диагностики.
