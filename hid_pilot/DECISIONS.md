# Архитектурные решения HID Pilot

## 2026-10-22 — Сброс COM/HID вместо ALT+TAB и тихая ручная остановка

По запросу пользователя удалены резервные ALT+TAB и SwitchToThisWindow.
После трёх отказов foreground переоткрывается COM-сессия Pico, выполняются
HELLO/STATUS DISARMED и повторный foreground без игровых команд. ARM
разрешён только после проверки окна. Таймеры/статистика сохраняются,
pause_generation инвалидирует историю наблюдений. Неудача завершает сценарий.
MainWindow.stop устанавливает тихую ручную остановку до отмены worker:
STOP, отмена старта, hard-stop и закрытие GUI не отправляют Telegram.
Ошибки самого сценария и штатное завершение продолжают уведомляться.

## 2026-10-22 — Таймаут pipe завершённого helper активации

subprocess.TimeoutExpired при communicate(.1) после завершения helper больше
не выходит из стратегии как необработанная ошибка. При exit code 0 допустим
отсутствующий stdout, как для windowed EXE; ActionController всё равно обязан
проверить целевой foreground/PID/геометрию перед ARM. Неуспешный exit code
с таймаутом ответа становится RuntimeError и проходит обычные три попытки.
Таймаут дочитывания pipe при очистке логируется, не перекрывая STOP или
исходную ошибку. Подтверждение успешного переключения остаётся обязательным.

## 2026-10-22 — Единый откат общей кнопки хила

В пользовательском сценарии F9 одновременно назначена на одиночный и
пати-хил. Независимый таймер пати-хила 5 секунд обходил heal_cooldown 12.
Добавлен учёт по физической кнопке окна хиллера: одинаковая кнопка использует
максимальный откат всех своих лечебных назначений. Разные кнопки пати-хила
сохраняют независимый таймер. Существующие настройки не изменяются.

## 2026-10-22 — Баффы по таймеру в бою и сохранение цели для лута

Уточнение пользователя: таймер баффов проверяется внутри боевого цикла,
а не только между убийствами. При HP МА >buff_min_hp (50% по умолчанию)
состояние attacking/недавний урон не блокирует запуск. Порог зелья независим.
Каст МА прерывается при HP <=порога, начатый макрос баффера сохраняет прежнюю
защиту от прерывания. После каста снимается свежий кадр, замеры урона начинаются
заново, атака возобновляется только после проверки цели.

Исправлена потеря лута при защите: Duo.observe больше не делает next target
по мёртвой цели и не меняет пропавшую цель внутри активного боя до verify.
Сначала подтверждение смерти и один подбор 1000 мс, затем поиск нового моба.
Срочный next target вне активного боя при новом уроне сохраняется.

## 2026-10-22 — Восстановление сценариев, ролей LU4 и статистика дуо

В существующем QSettings сохраняются пути соло/дуо и идентификаторы ролей
окон. При открытии загружаются файлы, восстанавливается активная вкладка,
МА и баффер. После перезапуска клиента допускается только уникальное
совпадение полного заголовка; порядок EnumWindows не определяет прежние роли.
При отсутствии истории и ровно двух LU4 используется первый порядок списка.
Неоднозначные сохранённые роли требуют ручного выбора, ввод не запускается.
Панель дуо получает тот же publish_statistics через отдельный Qt-сигнал,
что обеспечивает цель, пати и счётчики убийств без повторного наблюдателя.

## 2026-10-22 — Пауза 0.2 секунды после Pico ALT+TAB

После подтверждения целевого окна и отпускания ALT контроллер держит HID
disarmed ещё 0.2 секунды. STOP, hard-stop, ручная пауза и потеря фокуса
прерывают ожидание. После задержки повторно подтверждаются RELEASE,
отпускание ALT в Windows и целевой foreground. Только затем разрешается ARM
и последующий игровой ввод. Обычное переключение без ALT+TAB не замедляется.

## 2026-10-22 — Три попытки foreground

По запросу пользователя число повторов foreground снижено с 10 до 3.
После трёх отказов остаются системный переключатель и Pico ALT+TAB,
с сохранением барьера отпускания ALT перед ARM и игровыми нажатиями.
Ручной STOP/START дополнительно переоткрывает COM/HELLO и активирует окно
после пользовательского клика; эти изменения могут объяснять восстановление,
но конкретная причина отказа без дополнительных наблюдений не подтверждена.

## 2026-10-22 — Барьер отпускания ALT перед игровым вводом

После сообщения пользователя о зажатом ALT одного STOP после ALT+TAB
недостаточно для продолжения ввода. ActionController перед каждым нажатием
клавиши, сочетания или кнопки мыши подтверждает RELEASE платы и ждёт,
пока Windows GetAsyncKeyState покажет отпускание ALT/LALT/RALT.
Предел ожидания — 0.2 секунды; ошибка ACK или зажатый ALT останавливают сессию
без следующего нажатия. После резервного переключения тот же барьер проходит
до проверки целевого foreground и повторного ARM.
Прошивка дополнительно отправляет нулевой keyboard report перед каждой
KEY/CHORD/BUTTON. Отдельные KEY ALT/LALT/RALT запрещены на ПК и Pico;
ALT+TAB остаётся только в специальной disarmed-команде переключения.

## 2026-10-21 — Непрерываемый баффер, MP и Pico ALT+TAB

Уточнение пользователя заменяет прежнюю отмену баффа хиллера при любом уроне.
МА может прерывать собственный бафф для защиты; начатый макрос баффера
продолжается до конца buff_seconds. Визиты с лечением, ассистом и follow
откладываются, кроме HP баффера <20%: тогда отмена, спасение и повтор баффа.
Перед полным баффом нужно известное MP >=support_buff_min_mp (60%).
Состояние баффа хранится между циклами боя и завершается по активному времени.
GUI не отключает всю вкладку, статусы обновляются рабочим capture.

По прямому запросу пользователя обновлена прошивка Pico: V5 добавляет SWITCH
ALT+TAB 80 только при disarm, с deadline освобождения. ПК сохраняет совместимый
набор обычных команд V4 и отдельно определяет возможность SWITCH по HELLO V5.
ActionController использует его после неудачи предыдущих стратегий, проверяя
исходное и целевое окна, hard-stop и отказ при переходе в чужое приложение.
Игровые скрипты по-прежнему не могут вызывать OS-сочетания клавиш.

## 2026-10-21 — МА, приоритет боя и отложенные параллельные баффы

По запросу пользователя основной персонаж называется МА (Мейн Ассистер).
Первый бафф обоих персонажей задерживается на buff_delay_minutes (5 минут).
Сроки ребаффа проверяются между боями, не внутри observe. Полный макрос хиллера
и селф-баффы МА запускаются параллельно; касты МА проверяют свежие HP каждые
0.2 секунды. Урон по МА/хиллеру прерывает баффы, инициирует агр и ответный бой.
Незавершённые слоты остаются ожидающими, завершённые сохраняют свой таймер.
Кнопка агра — aggro_key (2 в сценариях); она исключается из overhit/урона.
Пати-хил хиллера назначен на F2, использует HP его строки пати МА и собственный
откат независимо от одиночного хила. GUI показывает HP обоих и ожидающие баффы.

## 2026-10-21 — Баффы, вампирик и настройки мили/дуо по группам

Три независимых слота баффов и вампирик добавлены в MeleeConfig/MeleeFarmer;

Второе окно получает отдельные зелье, собственный вампирик и пати-хил.
HP саппорта берётся из свежей строки пати фармера; перед вампириком используется
существующий игровой ассист. Каст ожидается после возврата окна фармера.
Общая форма FarmSettings группирует параметры и изменяет исходный set-сценарий,

## 2026-10-21 — Резервный переключатель после десяти отказов foreground

По запросу пользователя после десяти неудачных helper-попыток запускается
отдельная стратегия task_switch: SwitchToThisWindow для известного HWND.
Она не повторяет SetForegroundWindow/AttachThreadInput и не отправляет
клавиатурный ALT+TAB: текущая прошивка не разрешает такое сочетание. Новая
стратегия выполняется тем же изолированным helper с проверкой HWND/PID,
геометрии, исходного foreground и результата. Таймаут, отмена и disarm
сохраняются; ARM разрешён только после независимой проверки окна контроллером.
После неудачи обеих стратегий сессия останавливается. SwitchToThisWindow
может быть недоступен на будущих Windows; отсутствие API означает отказ,
а не разрешение ввода. Плата не перепрошивается, поставка не пересобирается.

## 2026-10-21 — Изолированная активация вместо ALT

Повторный live-отказ SetForegroundWindow показал, что одиночного ALT недостаточно.
Запасной путь заменён скрытым короткоживущим процессом window_activation.
Сначала он делает прямой запрос; при отказе временно присоединяет свою очередь
к исходному foreground-потоку через AttachThreadInput и повторяет активацию.
Исходный HWND/PID, геометрия обоих окон и foreground проверяются перед запросом;
очередь отсоединяется в finally. Parent каждые 10 мс проверяет STOP/PAUSE/hard-stop,
завершает helper при отмене/timeout и независимо подтверждает окно до ARM.
При возможном зависании чужого Win32 потока блокируется только helper, а не
ActionController. Во время попытки Pico остаётся disarmed, ALT не отправляется.

Helper использует только стандартную библиотеку и Win32, без Qt/OCR. В исходниках
запускается отдельным Python-процессом; entrypoint будущей EXE-поставки обрабатывает
--activate-window до загрузки GUI. Consoleless helper может отвечать кодом выхода;
код 0 означает проверенный foreground. Права наследуются от запустившего Pilot,
автоматического повышения прав и UAC-запроса нет. Диагностический процесс обычного
уровня получил код 5 при присоединении к административным клиентам; это не live-
приёмка elevated-пути. Сборка поставки не выполнялась.
Native smoke на двух временных окнах одинакового уровня прав: четыре успешных
переключения с реальным AttachThreadInput (первый прямой запрос намеренно
отклонялся тестовым адаптером). Окна закрыты, исходный фокус восстановлен.

## 2026-10-21 — Отказ SetForegroundWindow при переключении Duo

После сообщения пользователя об ошибке `(0, SetForegroundWindow, ...)`
activate сначала проверяет фактический foreground HWND. Ошибка Win32 не
считается отказом, если нужное окно уже получило фокус. Иначе поднимается
понятная ActivationDenied с именем окна/PID/кодом ошибки.
ActionController один раз повторяет активацию после одиночного ALT 40 мс
через Pico V4: исходное окно и hard-stop проверяются перед вводом, назначения
PID/геометрия перепроверяются, STOP/disarm выполняется до и после ALT.
Это использует документированное поведение Windows для foreground lock.
AttachThreadInput не используется из-за риска синхронного зависания на
чужой очереди сообщений. Подтверждение фокуса остаётся обязательным; повторный
отказ останавливает сессию. Автотесты используют подставные Win32/Pico;
переключение реальных клиентов требует повторной ручной проверки.

## 2026-10-21 — Duo как наследник базового мили-фарма

По прямому запросу пользователя упрощённый цикл Duo заменён наследованием:
DuoFarmer(MeleeFarmer), DuoConfig(MeleeConfig). Общий run_cycle сохраняет

Два узких расширения базы: обработка того же свежего кадра и pickup_loot;
обычный мили-фарм сохраняет прежнее поведение. Duo добавляет переключения,
ассист после первой атаки, приоритетный хил, следование и периодический бафф.
Наблюдение и статистика запускаются/закрываются тем же способом, что в мили.
Требуется HID_PILOT_V4; OCR подготавливается до подключения Pico.

Пользовательские клавиши и параметры из farmer-healer.duo.json перенесены
с приоритетом над настройками farm_melee.pilot. F11/F10/F10/F9, 6/3/C,

полей преобразуются при чтении; конфликтующие значения отвергаются. Профили
и разметка окон не меняются. Сборка поставки не выполнялась.

## 2026-10-21 — Периодический бафф и защитная атака в Duo

По уточнению пользователя бафф повторяется каждые rebuff_minutes (19 минут
по умолчанию) активного времени. Ребафф отменяет текущую атаку параметром
stop_attack_key и прерывает обычный цикл; после баффа цель выбирается заново.
Во время баффа разрешена только защитная атака при наблюдаемом падении HP/CP
фармера либо HP бафера (уточнение пользователя: признак — его HP в пати).
Полоса HP бафера читается из явно заданной строки пати
support_party_slot в окне фармера, без переключений на бафера для наблюдения
и без OCR имён. Профиль пати проверяется до подключения Pico.
Сравнение ограничено свежими кадрами одной эпохи паузы; неизвестные значения
разрывают сравнение. После двух секунд без нового падения атака прекращается.
Низкий постоянный HP не считается входящим уроном. Таймер, порог шума,
окно актуальности урона и клавиши остановки/выбора нападающего конфигурируются.
Реакции игровых макросов требуют ручной проверки; поставка не пересобиралась.

## 2026-10-21 — Общая HID-сессия для двух окон

По запросу пользователя добавлен отдельный сценарий фармер + бафер/хилер.
Один ActionController и один Pico сериализуют весь ввод; независимых watchdog
и транспортов для двух окон нет. Переключение выполняет ActionController:
STOP/release/disarm, проверка исходного окна, PID/геометрии назначения,
ограниченное ожидание фокуса, ARM. Ошибка останавливает всю сессию.
Потеря фокуса пользователем сохраняет прежнюю автопаузу без перехвата окна.

Новый детерминированный DuoFarmer запускает стартовый бафф, следование,
атаку фармера, макрос ассиста помощника и лут после подтверждения смерти.
Свежий HP фармера проверяется с приоритетом хила; во время короткого визита
помощника наблюдение фармера отсутствует. Отдельный поток screen capture
не создаётся, скрытые пиксели не выдаются за данные игрового окна.
Сценарий *.duo.json выбирается отдельно от *.pilot. Два одинаковых PartyPanel
используют существующий диалог настройки с раздельными путями профилей.
Основная архитектура и milestone L2 Agent не меняются. Настройка и ограничения:
[DUO.md](DUO.md). Сборка поставки не выполнялась; live-проверка двух клиентов
и игровых макросов остаётся ручной.

## 036 — F8 только для скиллов и снижение повторного OCR, 2026-10-08

Переключения F8 без лечения вызывала обёртка клавиши следования 9.
Она удалена: движение, лут и пустые циклы не включают ауру. Таймер
выключения остаётся только после лечебных/поддерживающих скиллов.

при неизменившихся текстовых масках; неуверенные имена повторяются
не чаще раза в 2 секунды. Временная потеря имени не считается сменой
состава и не запускает циклическую переразметку. Собственный OCR использует
общий последний кадр вместо дополнительного capture, интервал worker
0,3 секунды. Частота быстрых полос пати не снижена. EXE не пересобирается.

## 034 — Фоновый OCR сессии, буфер статов и ESC, 2026-10-08

SessionPerception закрепляет области подтверждённых профилей на время
сессии. Устойчивое изменение состава или потеря статов запускают OCR
только внутри этих областей. Результат принимается при единственном
кандидате; revision защищает клики от смешения старого кадра с новой
разметкой. Буфер CP/HP/MP ограничен одной секундой исходного наблюдения,
OCR работает отдельным worker без блокирования быстрого чтения полос.
Потеря ресурсов откладывает ввод и запускает перепоиск вместо остановки.

## 013 — Внешние расширения сценариев, 2026-10-05

По указанию пользователя алгоритмы хила и фарма вынесены из компилируемого ядра
в `extensions/hid_pilot`, сценарии — в `extensions/scripts`. PyInstaller исключает

и загружается рядом с EXE, а не из временного `_MEIPASS`.

конфигурации, preflight и запуск. Parser, Runner и GUI не содержат конкретных
алгоритмов. Вторая конкретная область использования — farm — оправдывает общий
загрузчик. Новые команды подключаются через манифест без пересборки ядра.
Единственный путь игрового ввода остаётся ActionController, с фокусом, hard-stop

# 2026-10-13 — Уточнение: сначала массовое лечение, затем точечное при продолжающемся уроне

## 2026-10-14 — быстрые статы фарма и фоновая идентичность

Оставляем capture и числовые HP/MP/CP в боевом цикле, а имя цели, уровни и пати

Обновление счётчика публикуется сразу после проверки второго кадра, до лута.
## 2026-10-14 — общая локальная база и подтверждения имён OCR

Один результат боя не записывает неподтверждённый OCR в общую базу.
Общая база ограничена 4096 именами; список /target ограничен текущей сессией.

## 2026-10-15 — overhit независимо от OCR имени

Исключена зависимость сбора HP-delta от подтверждённого имени. Безымянные цели
используют оценку текущего боя, без переноса процентов HP между разными мобами.

## 2026-10-16 — подготовка OCR до ARM Pico и ранний выход из /target

В журнале старта farm_melee подтверждены обрывы heartbeat с неполными CDC-ответами

## 2026-10-17 — ограниченный выход из недоступной цели в мили-фарме

Пять последовательных боёв без снижения HP по одному подтверждённому имени
запускают две ограниченные попытки выхода: случайная пара WA либо SD,
попеременные удержания по 1500 мс, 20–30 удержаний за попытку. Между попытками
отправляется rest (сесть/встать). Успешный урон сбрасывает счётчик; неизвестное
имя не позволяет объявить повтор доказанным. Это эвристика по типу/имени моба,
а не подтверждение идентичности отдельного игрового объекта.

После удержания и next target проверяется собственное HP; урон прекращает выход
и передаёт живую выбранную цель в бой. Другое подтверждённое имя также разрешает
немедленный бой. Продолжение реализовано циклом, без накопления рекурсивных вызовов.
Пауза отменяет выход, STOP и лимит сессии не обходятся. После двух неудачных
попыток возвращаемся к обычному поиску. Сброс цели ESC и проверки игрока/NPC сохраняются.

## 2026-10-18 — перебор имён после недоступной цели

Мили-фарм перемешивает известные имена для /target и сохраняет неиспользованный
остаток между поисками. Успешное выделение не начинает перебор заново.

имя исключается из обычного поиска на 60 секунд; после двух безуспешных
попыток выхода этот срок отсчитывается заново. Подтверждённое имя после
next target проверяется перед боем, недоступная цель сбрасывается через ESC.

## 2026-10-18 — ограничение уровня цели в мили-фарме
