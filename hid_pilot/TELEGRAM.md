# Уведомления Telegram

HID Pilot отправляет уведомление при завершении исполнения сценария:
обычное завершение или ошибка. Ручной STOP, аварийная горячая клавиша,
отмена отложенного старта и закрытие GUI не отправляют сообщение. Оно содержит
имя сценария, выбранное окно, причину и длительность. Повторные нажатия STOP
не создают отдельные сообщения: уведомление формируется один раз в конце
worker, после освобождения контроллера. Быстрые клавиши тоже поддерживаются.
Пауза сама по себе уведомление не отправляет.

При подтверждённом собственном HP = 0 также отправляется сообщение
«персонаж умер» с именем сценария и окна в тот же канал/чат.
Ожидание Accept не задерживается сетью. Повторные кадры смерти не создают
новых сообщений; после воскрешения следующая смерть уведомляется снова.

## Настройка

При открытии пилота создаётся файл `%LOCALAPPDATA%\HIDPilot\telegram.toml`.
Существующий файл не перезаписывается. Его можно открыть через меню
«Файл → Открыть конфиг Telegram» либо из папки файлов приложения.

```toml
[telegram]
enabled = true
token = ""
chat_id = ""
notify_on_stop = true
notify_on_death = true
timeout_seconds = 5
```

В `token` запишите токен вашего бота, в `chat_id` — ID получателя, например
вашего личного чата или группы. Для группы ID может быть отрицательным;
строка и целое число поддерживаются. Для канала можно указать `@username`.
Бот должен иметь возможность отправлять сообщения в выбранный чат:
для личной переписки сначала откройте бота и нажмите Start, для группы
добавьте бота с правом отправки сообщений.

По умолчанию уведомления об остановке включены, но пока токен и Chat ID
не заполнены, сетевых запросов нет. `enabled = false` отключает интеграцию,
`notify_on_stop = false` отключает уведомления об остановке.
`notify_on_death = false` независимо отключает уведомления о смерти.
В существующих конфигах без этого поля уведомления о смерти включены.
Настройки перечитываются перед каждой отправкой; для их изменения перезапуск не нужен.
Реальный токен храните в пользовательском конфиге, не в сценарии или репозитории;
имя `telegram.toml` добавлено в `.gitignore`.

## Отправка и диагностика

Используется HTTPS POST метода [sendMessage Telegram Bot API](https://core.telegram.org/bots/api#sendmessage),
без дополнительных Python-зависимостей. Сообщения отправляются отдельным
daemon-потоком с очередью максимум восемь событий и сетевым timeout 1–15 секунд
(по умолчанию пять). GUI, hard-stop и HID не ждут Telegram.
Автоматического повтора HTTP-запроса нет, чтобы не дублировать уведомление
после неизвестного результата доставки. Ответы API проверяются.

Ошибки настройки/сети и успешная доставка отмечаются в `hid-pilot.log`.
Токен, URL с токеном и содержимое исключений HTTP не выводятся в журнал.
Принудительное завершение процесса не позволяет выполнить уведомление;
если закрыть приложение до окончания фоновой отправки, доставка не гарантируется.

Тесты используют подставной HTTP-клиент. Проверка реальной доставки требует
заполненного конфига; тестовых сообщений автоматически не отправляется.
