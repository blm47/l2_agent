# HID Pilot

Дуо-фарм МА + саппорт в двух окнах: [DUO.md](DUO.md).

Запись пяти минут фарма при смерти через OBS: [RECORDING.md](RECORDING.md).
Оставшиеся проверки и бэклог: [docs/TODO.md](../docs/TODO.md).

Распознавание типа цели и минутная статистика мобов: [TARGETS.md](TARGETS.md).


Самостоятельное Windows-приложение для текстовых макросов через Pico HID.
Не зависит от L2 Agent, LLM или сетевого наблюдения. Это собственный язык,
совместимость с синтаксисом UoPilot не заявляется.

## Запуск

Готовая автономная сборка Windows x64: `dist/HID_Pilot.exe` (один файл).
Python, pip, OCR-модели и интернет на рабочем компьютере не требуются.
Скопируйте EXE в удобную папку и запустите. Альтернатива — распаковать весь
`dist/HID_Pilot_Portable-0.2.0.zip` и запустить EXE из папки; `_internal` должен
оставаться рядом с ним. Инструкция — `dist/QUICKSTART.txt`.

Меню «Файл» открывает папку примеров и пользовательские файлы. Логи, примеры
и резервные копии хранятся в `%LOCALAPPDATA%\HIDPilot`, поэтому приложение
можно запускать из папки без прав записи. При первом открытии папки примеров
копируются только `.pilot`; собственные изменения не перезаписываются.
Профили HP/MP/пати нужно калибровать на новом компьютере под его окно и DPI.

Из корня репозитория с уже установленными зависимостями:

```powershell
cd hid_pilot
..\.venv\Scripts\python.exe -m hid_pilot
```

Для отдельной установки: Python 3.12, `pip install -e .` в этой папке,
затем `hid-pilot`. Для тестов дополнительно нужен pytest.

В GUI: выберите окно и CDC data port Pico. На вкладке «Общее» доступны четыре
строки: клавиша (или ЛКМ/ПКМ), пауза после отпускания в миллисекундах и число
повторов. `-1` повторяет до STOP, с общим ограничением запуска в один час.
Кнопка «Старт» запускает одну строку; «Старт отмеченных строк» — все отмеченные
со своими интервалами, без одновременных удержаний. ЛКМ/ПКМ нажимаются в текущей
точке курсора, которая должна находиться внутри выбранного окна.

На вкладке «Скрипт» можно открыть/написать сценарий и проверить синтаксис.
START один раз активирует выбранное окно и запускает ввод через секунду.
Игра LU4 выбирается по умолчанию, если найдена; выбор сохраняется при обновлении.
Потеря фокуса или сворачивание окна включает автопаузу с освобождением ввода.
Возврат в то же окно продолжает сценарий; смена геометрии, PID или закрытие окна
останавливает исполнение. STOP и глобальная клавиша `\` освобождают ввод.

## Прошивка

Меню «Pico контроллер → Прошивка / сброс / проверка…» обслуживает платы
Raspberry Pi Pico и Pico W на RP2040. В EXE встроены CircuitPython 10.3.1,
`boot.py`, `code.py`, `control.py` и официальный UF2 полного сброса.
Pico 2 / Pico 2 W и сторонние RP2040-платы в этой сборке не поддерживаются.

Первый запуск новой платы:

1. Подключите USB data cable с зажатой BOOTSEL, выберите диск RPI-RP2 и модель платы.
2. Нажмите «Установить CircuitPython», дождитесь появления CIRCUITPY и обновите список.
3. Выберите CIRCUITPY и нажмите «Установить / обновить HID Pilot».
4. Безопасно извлеките CIRCUITPY в Windows, переподключите USB без BOOTSEL.
5. Обновите список и нажмите «Проверить прошивку». После успешной проверки CDC data port
   переносится в главное окно.

Проверка сопоставляет SHA256 трёх файлов с встроенными исходниками, проверяет
HELLO `HID_PILOT_V3` и STATUS `DISARMED`. Без выбранного CIRCUITPY проверяется
только связь/протокол — это явно отмечается в результате. ARM, клавиши и клики
при проверке не отправляются. Для обновления приложения на работающей плате
обычно достаточно шагов 3–5.

Перед заменой файлов автоматически сохраняется ограниченная копия CIRCUITPY
в `%LOCALAPPDATA%\HIDPilot\pico-backups` с SHA256 и идентификацией носителя.
Копирование не включает образ CircuitPython или NVM. Доступна отдельная кнопка
сохранения копии перед переходом в BOOTSEL. Пока открыто обслуживание Pico,
сценарии не запускаются; работающий сценарий нужно сначала остановить.

Полный сброс — отдельная команда только для явно выбранного RPI-RP2, с checkbox
и подтверждением удаления. Она стирает всю flash-память платы, включая файлы,
CircuitPython и NVM. После неё установите CircuitPython и HID Pilot заново.
Запись UF2 сама по себе не считается проверенной установкой: финальная проверка
проходит после переподключения. При обрыве USB резервная копия остаётся на ПК;
восстановите нужные файлы из подпапки `files` либо повторите установку.

UF2 загружаются только при подготовке сборки, из
[CircuitPython Pico](https://circuitpython.org/board/raspberry_pi_pico/),
[CircuitPython Pico W](https://circuitpython.org/board/raspberry_pi_pico_w/) и
[Raspberry Pi flash_nuke](https://datasheets.raspberrypi.com/soft/flash_nuke.uf2).
URL, timestamp и SHA256 закреплены в `firmware/vendor/manifest.json`.

Подготовлена отдельная `firmware/` для CircuitPython на существующем Pico:
`boot.py`, `code.py`, `control.py`. На плату автоматически ничего не записывается.
2026-10-04 по явному запросу пользователя установлен HID_PILOT_V3 на Pico
UID `5303284718697D9C` (COM4). HELLO подтвердил V3, STATUS — DISARMED;
SHA256 control.py на плате совпал с исходником. Резервная копия прежней V1:
`../artifacts/hid-pilot/pico-backup-before-v3-20261004/`.
Поддержаны протоколы `HID_PILOT_V3`, `HID_PILOT_V2`, `HID_PILOT_V1` и `L2_PICO_V1`. На старой прошивке работают
клавиши и клики в текущей точке. Для наведения курсора нужен HID_PILOT_V1;
попытка движения со старой прошивкой отклоняется без отправки MOVE.
При замене прошивки для возврата к L2 Agent понадобится вернуть его вариант.

Клавиши, кнопки и относительное движение мыши передаются через USB HID.
SendInput не используется. Положение курсора только читается через Win32.
Наведение ограничено 8 секундами; при отклонении больше 2 пикселей клик отменяется.
Из-за ускорения мыши возможна остановка при невозможности точного наведения.
Перед движением курсор уже должен находиться внутри целевого окна.

Плата ограничивает удержания 1–1000 мс, перемещения ±16 HID counts и
освобождает ввод при потере heartbeat на 350 мс. Host watchdog проверяет
окно каждые 25 мс. Это не жёсткие real-time гарантии Windows/USB.

## Сценарии

### Фарм и калибровка полос

Кнопка «Автопоиск HP / MP / CP / цели / пати…» на вкладке «Скрипт» снимает выбранное окно
и ищет числовые пары через OCR в фоне, без игрового ввода. По умолчанию
для цифр сканируется верхняя треть; для перемещённых панелей выберите «Всё окно».
Пати ищется по всему кадру по тройкам цветных CP/HP/MP и имени над ними.
Сценарий должен быть остановлен и сохранён.

Результат открывается на снимке с выделенными ROI. Метки HP/MP/CP помогают
различить ресурсы персонажа; CP не назначается как HP. HP цели без метки
предлагается только при единственной паре справа от панели персонажа.
Это предложение, требующее проверки. При неоднозначности список остаётся
без выбора. Для каждого поля можно выбрать найденный вариант или отказаться от него.
Ручное рисование ROI и отдельные кнопки выделения полос/цифр убраны.
Пати подсвечивается в том же окне: первый участник и область до восьми строк.
Шаг строк можно уточнить числом; при одном участнике он предварительный.

«Сохранить» записывает подтверждённые числовые области в farm-bars.json рядом
со сценарием, а пати — в party.json. Новый поиск заменяет старые ручные ROI.
Выбор «не использовать» для пати удаляет прежний профиль пати.
«Отмена» сохраняет прежние профили. Если окно изменило PID или
геометрию за время поиска/просмотра, предложения отклоняются. Фарм не запускается
после поиска автоматически.

Автопоиск и новая ручная обводка добавляют к OCR-областям собственных HP/MP/CP,
HP цели и цифр уровня запас по 20% исходной ширины слева и справа.
Область имени/панели цели расширяется на 60% вправо для более длинных имён.
Высота сохраняется, запас ограничен границами кадра и сразу виден на рамке.
Повторное сохранение не расширяет область; ранее сохранённая разметка остаётся прежней
до новой обводки или автопоиска. Цветные полосы ресурсов не расширяются.
Надёжно распознанные цифры имеют
приоритет над цветовой полосой: 0/58 и 0/112 дают нулевое HP без образца смерти.
Допускаются только числа с current <= maximum и maximum > 0, confidence >= 0.9.
При расхождении двух вариантов обработки OCR результат неизвестен; используется
цветовая полоса, если она настроена. Цифровые ROI могут работать без полос.
Если через пустую полосу трупа просвечивает соседняя строка игрового мира,
числовой OCR отделяет полные строки по маске светлых символов и исключает строки,
обрезанные краем ROI. Противоречащие числовые пары остаются неизвестными;
нулевой HP каждый раз распознаётся заново и не берётся из кеша.

OCR использует ленивую CPU-модель RapidOCR, без LLM и GPU. В общей .venv
зависимость уже установлена. Для самостоятельной установки: `pip install -e ".[ocr]"`.
На сохранённом игровом кадре проверены 129/129 HP, 104/109 MP и 0/58 HP цели.
Это проверка на сохранённом изображении; live стабильность требует проверки
с выбранными пользователем цифровыми ROI. Новая настройка не меняет прошивку Pico.

Пример: `extensions/scripts/farm.pilot`. Все параметры заданы в начале через `set`.
`pickup_loot true` включает подбор (по умолчанию); `false` отключает.
Клавиша отдыха задана как `set rest =`. Для неё требуется обновлённая прошивка
HID_PILOT_V1 из этой папки; со старой прошивкой фарм отклоняется до первого нажатия.

Откройте и сохраните сценарий, выберите живого моба и выполните автопоиск.
Пати ищется сверху вниз даже при частично заполненных HP/MP. Правый край CP
используется как предварительная граница полной длины; проверьте её перед сохранением.
Автопоиск требует различимых троек полос и хотя бы одного уверенного имени в колонке;
непрочитанное имя первой строки не сдвигает нумерацию остальных.
Профиль `farm-bars.json` сохраняется рядом со сценарием. Изменение размера
клиентской области требует повторной калибровки. Старые ROI L2 Agent не импортируются.

Цикл: next_target → R пока HP цели >10% → 4 до подтверждённого HP цели = 0 →
несколько попыток 5 → новая цель. Собственные HP/MP проверяются между действиями
и каждые примерно 0.3 секунды в ожиданиях. При HP <50% вызывается макрос 2;
после него выбирается новая цель, поскольку макрос выбирает себя. Это не
гарантирует возврат к тому же мобу. При MP <10% живую цель добиваем клавишей 4;
отдых до 90% разрешён только после подтверждённой смерти цели. Потеря полосы
цели, в том числе после лечения, не снимает запрет отдыха.

При неизвестных HP/MP выполняются до `observation_attempts` свежих замеров
(по умолчанию 5), с паузой `observation_delay` (0.5 секунды). Первый повтор
проходит без движения, перед следующими — короткие нажатия W/A/S/D по 100 мс
для обновления интерфейса. `set observation_movement false` отключает движение;
сидящий персонаж также не двигается. Если распознавание не восстановилось,
фарм останавливается после исчерпания попыток. Проверки фокуса и hard-stop
продолжают действовать через ActionController.
Входное условие: персонаж стоит. Если STOP произошёл во время отдыха, он может
остаться сидеть: после STOP никакие клавиши автоматически не отправляются.

Если после атак HP цели не снижается `stuck_timeout` секунд (по умолчанию 5),
сценарий нажимает `melee` (4) для сближения, ждёт `reposition_delay` секунд
(по умолчанию 3) и продолжает атаковать. Это реакция на отсутствие прогресса:
сообщение «не видно цель» из чата пока отдельно не распознаётся.
Во время сближения проверки собственного HP/MP продолжаются. Максимум
`reposition_attempts` безуспешных попыток (по умолчанию 3), затем остановка.
Снижение HP сбрасывает счётчик; рост HP его не сбрасывает. `progress_epsilon`
(0.002 = 0.2 процентного пункта) отсекает дрожание цветовой оценки;
уменьшите его, если реальные удары снимают совсем небольшую долю HP.
Общий `combat_timeout` включает сближения и не продлевается.
Новые параметры имеют defaults и работают также в ранее сохранённых сценариях.

Сближение и успешный подбор не подтверждаются визуально: approach_delay и
loot_attempts нужно настроить под персонажа. Невидимая/полностью пустая полоса
не считается нулём HP без дополнительного признака. Ноль подтверждается OCR
надписи `0 / максимум` в найденной области: после атаки выполняется подбор
без повторной атаки 4. Исчезновение панели остаётся неизвестным состоянием. Если
next_target оставляет уже мёртвую цель, выбор повторяется ограниченное число раз.
Нераспознанное HP/MP, таймаут
лечения, боя или отдыха останавливают ввод. Фарм не запускается автоматически.

### Выбор цвета

Кнопка «Цвет в точке» активирует выбранное окно, снимает его клиентскую область
и показывает снимок поверх игры. Клик вставляет в текущую позицию редактора
`color x y RRGGBB 15` с координатами 0..1. Esc отменяет выбор. Клик поглощает
инструмент; действие в игру не отправляется. Сценарий должен быть остановлен.

Переменные: `set attack R`, затем `key $attack 100`. Все `set` должны находиться
в начале сценария; исполнять Python или shell через переменные нельзя.

### Базовые команды

Комментарии начинаются с `#`, строки шаблонов можно заключать в кавычки.
Пути относительны папке сохранённого сценария, для несохранённого — рабочей папке.

| Команда | Назначение |
|---|---|
| `wait 1.5` | Пауза в секундах, до 60 |
| `key R 100` | Удержание клавиши в миллисекундах |
| `move 0.5 0.5` | Навести курсор в центр клиентской области |
| `click left 0.5 0.5` | Навести и нажать left/right |
| `find "button.png" 0.95 3` | Искать шаблон до 3 секунд, порог сходства 0.95 |
| `color 0.5 0.5 FF0000 15` | Проверить RGB в точке с допуском 15 на канал |
| `if_found` … `end` | Исполнить блок при свежем результате find/color |
| `click left` | Нажать в найденной точке; результат действителен 1 секунду |
| `repeat 3` … `end` | Повторить блок 1–1000 раз |

В HID_PILOT_V3 поддержаны все клавиши стандартной 104-клавишной клавиатуры,
кроме `\` (hard-stop): A–Z, 0–9, F1–F12, пунктуация, стрелки, навигация,
NumPad и модификаторы. Полные имена и примеры — [firmware/KEYBOARD.md](firmware/KEYBOARD.md).
Комбинации нескольких клавиш не поддерживаются. Лимиты: 8 вложенных блоков,
100000 исполняемых инструкций и 1 час на запуск.

## Границы первой версии

START/STOP, редактор, циклы, условия, цвет и поиск шаблона реализованы.
Ручная пауза включается и снимается мышью через PAUSE / RESUME. F9 свободна
для игровых скиллов. Переключение в GUI уже включает автопаузу; нажатие PAUSE
закрепляет ручную паузу, которая сохраняется и после возврата в игру.
После RESUME сценарий ждёт активации выбранного окна. Прерванное удержание
не повторяется. Wait, наведение и таймеры фарма не расходуются во время паузы;
реальные откаты и эффект Invocation продолжают отсчитываться.
После STOP новый START начинает заново. Общий часовой лимит запуска сохраняется.
Нет записи действий и редактора вырезания шаблонов. OCR ресурсов и имён пати,
а также переменные сценария поддерживаются.
Capture снимает видимые пиксели клиентской области через GDI; перекрытие окна,
масштаб UI и полноэкранный режим могут влиять на поиск. Совпадение изображения
не устанавливает смысл объекта. Снимки не сохраняются автоматически.
GUI и лог показывают исполняемую строку. Реальные HID-движения с новой прошивкой
и работа CV на конкретном игровом окне требуют аппаратного smoke-теста.

Повтор smoke отправляет реальные R: `python smoke_quick.py`.
При переключении из игры в GUI работающие строки автоматически приостанавливаются;
возврат в игру продолжает их, если не включена ручная пауза. Приложение не нажимает клавиши
в фоновых окнах и не перехватывает фокус обратно во время выполнения.

## Восстановление MP и пати

Во время восстановления каждые 2 секунды журнал показывает HP, текущий MP,
источник (`OCR 148/148` либо полоса), порог `mp_resume` и остаток `rest_timeout`.
Файловый лог — `%LOCALAPPDATA%\HIDPilot\logs\hid-pilot.log`.
Таймаут содержит последние измерения. Порог, достигнутый в последнем наблюдении,
проверяется до ошибки таймаута; автоматического увеличения лимита нет.

На вкладке «Пати» включите наблюдение и вернитесь в выбранное окно игры.
Профиль `party.json` ищется рядом с сохранённым сценарием. Для `extensions/scripts/farm.pilot`
уже есть профиль текущего окна 2189×1327. Имя первого участника проверено:
KuKaBaraBang; CP/HP/MP читаются по цветовым полосам, без выдуманных чисел ресурса.

Кнопка автопоиска на вкладке «Пати» открывает тот же общий поиск и проверку.
При нескольких участниках сохраняются отдельные смещения строк сверху вниз.
Дополнительные HP/MP питомца без CP не создают отдельного участника. При одной
найденной строке шаг предварительный; проверьте его при появлении остальных.

«Пати» → «Ручная корректировка пати…» открывает текущий `party.json` на свежем снимке,
без обязательного OCR. Выделите всю панель от первого имени до MP последнего участника.
При необходимости выберите имя, CP, HP или MP первого участника и выделите полную
область мышью. Кнопки масштаба позволяют приблизить пати или вернуться ко всему окну.
Проверьте все восемь рамок: обычный шаг задаёт интервал между строками, а поля
«После N, +px» добавляют место для питомца или другого промежутка. Например, для
снимка с ISatana в строке 4 и indik в строке 7 дополнительные интервалы стоят после 4 и 7.
«Сохранить» меняет только `party.json`; «Отмена» сохраняет прежнюю разметку.
Тот же редактор доступен в окне проверки общего автопоиска.

Старые профили с одним `row_step` продолжают работать. Новые могут содержать
`row_offsets` — восемь смещений в пикселях относительно первого участника.
Разметка фиксируется для текущего расположения. При изменении состава пати или
появлении/исчезновении питомцев проверьте и при необходимости обновите её.
Максимум 8 строк; при изменении размера окна требуется новая настройка.
Пустые/неразличимые полосы показываются как `?`; отсутствие распознанных строк
не отличает пустую пати от скрытой панели. Неактивное окно и устаревший OCR
дают «неизвестно», а старые имена не сохраняются. Сама вкладка пати только наблюдает.

## Сборка EXE из исходников

Сборка выполняется на Windows x64 с Python 3.12. Зависимости сборки закреплены:

```powershell
cd hid_pilot
py -3.12 -m venv .venv-build
.venv-build\Scripts\python.exe -m pip install -r packaging\requirements-build.lock
.venv-build\Scripts\python.exe packaging\build.py
.venv-build\Scripts\python.exe packaging\smoke_build.py
```

PyInstaller собирает один EXE и переносимую папку. OCR inference работает на CPU;
ONNX-модели RapidOCR, runtime DLL, библиотеки Qt, Win32, serial и OpenCV встроены.
В переносимую версию включены лицензии и ссылки на исходники зависимостей;
Qt DLL доступны для замены. Сборка не включает L2 Agent, ML-тренировку или CUDA.

`smoke_build.py` переносит оба варианта в папки с пробелами и кириллицей, убирает
PYTHONPATH/PYTHONHOME и пути установленного Python, запускает frozen self-test
с отдельным пользовательским каталогом. Проверяются OCR чисел и имён, UF2,
исходники прошивки, примеры DSL, Qt и доступность Win32. Записи на реальный Pico
и игрового ввода при этом нет. Результаты — `../artifacts/hid-pilot/standalone-smoke/`.

Для проверки на другом компьютере без платы:

```powershell
.\HID_Pilot.exe --self-test --report self-test.json
```

Проверка на реальной новой плате требует прохождения установки и подтверждения
HELLO/STATUS в меню Pico. Сам сборочный smoke не подтверждает аппаратную прошивку.
# Фарм воином и ручные статы (2026-10-13)

В панели наблюдения доступна кнопка «Вручную указать свои статы и уровни…».
На снимке выделяйте числа `текущее / максимум` для HP/MP/CP/HP цели,
а для уровней — только цифры слева от соответствующих панелей.
Подтвердите основное окно, чтобы сохранить `farm-bars.json`.

`farm_mage.pilot` — прежний фарм магом; `farm.pilot` сохранён для совместимости.
`farm_melee.pilot` — фарм воином. Настройте клавиши под свои игровые макросы:
по умолчанию next target — 6, атака — 4, лут — C, хил — 2, отдых — `=`.
После атаки воин ждёт снижения HP до 5 секунд; недоступная или исчезнувшая
цель ведёт к новому поиску. Убийства считаются только по подтверждённой смерти.
Лут удерживается 1,5 секунды без дополнительного сближения.
Перед отдыхом требуется 5 секунд наблюдения без урона по HP/CP.
При входящем уроне без цели сначала выбирается и добивается агрессор.

Если next target не находит цель, выполняются три случайных перемещения WASD
по 2–3 секунды с повторным поиском, затем перебираются известные монстры
через `/target`. Если ни один не выбран — фарм останавливается.
Подтверждённые имена и наблюдаемые уровни монстров сохраняются в общей базе
`%LOCALAPPDATA%\HIDPilot\monsters.sqlite3`; статистика текущего запуска выводится в панели наблюдения.
Пати необязательна. Нераспознанный уровень остаётся неизвестным.

Отдельный навык: `target_name "Cloudy Beast"`. Он выполняет Enter, Ctrl+A,
Backspace, ввод `/target имя`, Enter и правый клик внутри окна игры.
Нужны английская раскладка и имена латиницей; до ввода проверяется имя целиком.
Фарм воином и этот навык требуют **HID_PILOT_V4**. Исходники прошивки обновлены,
автоматическая установка на Pico не выполняется; EXE и dist не пересобирались.
# Дополнительный урон и overhit (2026-10-14)

`set overhit_during_combat true` разрешает использовать клавиши `overhit_keys`
как обычные боевые скиллы по `overhit_interval`, начиная с первого моба.
Готовый overhit-скилл приоритетен перед дополнительным уроном; при подходящем
остатке HP выполняется попытка добивания. Боевые применения и добивание
используют один откат каждой клавиши. Если overhit недоступен, обычная атака
продолжается и может добить моба без overhit. Подтверждённый бонус опыта не обещается.
Урон этих скиллов не записывается как обычный удар; включённый режим может
ограничивать сбор чистых данных для оценки среднего урона.
По умолчанию `overhit_during_combat false`: сохраняется режим только добивания
и исходное обучение по первым трём убийствам.

В `farm_melee.pilot` задайте отдельные списки клавиш:

```text
set damage_keys "F1,F2"
set overhit_keys "F3,F4"
set damage_interval 3
set overhit_interval 5
set overhit_margin 1.15
```

Пустой список `""` отключает соответствующие скиллы. Клавиши списков должны
отличаться друг от друга и от next target, хила, лута и отдыха.
Обычную атаку можно включить в `damage_keys` для повторения; overhit должен быть отдельным.
Интервалы ограничивают повтор каждого скилла; настройте их под его реальный откат.

Для фарма разрешены до 10000 циклов и `max_seconds 360000` (100 часов).
Внешний таймер сценария учитывает заданное `max_seconds`; значения по умолчанию
остаются 1000 циклов и 36000 секунд.

Первые три подтверждённых убийства служат обучению среднего обычного удара;
добивание при HP до 2% доступно с первого боя. Имя для оценки урона не требуется.
Оценка хранится отдельно по имени и уровню моба как доля его HP, обновляется
по последним 128 наблюдаемым снижениям и показывается в панели наблюдения.
Для нового вида моба сначала собирается его собственная оценка.
Исчезнувшие цели, неподтверждённые смерти, длинные промежутки между кадрами
и остаток HP при смертельном ударе не используются для обучения. После первого
дополнительного скилла новые снижения в этом бою тоже исключаются из оценки.

Когда HP цели не выше `средний удар × overhit_margin`, выбирается доступная
overhit-клавиша. При большем HP используются дополнительные атакующие скиллы.
Если цель уже выбрана с малым HP, макрос сначала пробует overhit.
При ожидании повторного overhit дополнительные атакующие скиллы не отправляются.
Успешное применение overhit и бонус опыта по одному HP не подтверждаются:
оценка приблизительная, автоатака и урон сопартийцев могут повлиять на результат.
# Быстрое наблюдение фарма (2026-10-14)

В фарме OCR имени цели, уровней и пати выполняется отдельным фоновым worker.
Оба OCR-engine загружаются на этапе подготовки сценария до подключения и ARM Pico,
чтобы тяжёлая инициализация не мешала heartbeat. Фоновый engine отделён от
числового OCR и повторно используется между запусками; watchdog платы не меняется.
Он хранит один последний кадр; кеш идентичности действует до 2 секунд и только
при совпадении текста панели на текущем кадре. Выбор новой цели и пауза сбрасывают кеш.
Изменение цифр HP и черепа не заставляет перечитывать имя.

Числовой OCR HP/MP/CP использует ограниченный кеш до 2 секунд только если маска
цифр совпала на новом кадре. Изменившиеся или исчезнувшие цифры не заменяются старым HP.
Цикл боя воина планирует чтение раз в 1/3 секунды с учётом времени обработки;
фактическая частота зависит от capture и числового OCR на компьютере.
Медленный проход OCR повторяется на свежем кадре, а не останавливает фарм немедленно.
В мили-фарме `observation_attempts 30` разрешает 30 попыток получить свежие
собственные HP/MP перед остановкой. В остальных сценариях фарма сохраняется
их собственное значение `observation_attempts`.

При восстановлении мили-персонажа новый поиск агрессора запускается только
при свежем падении собственного HP/CP между соседними наблюдениями с разрывом
не более секунды. Старый флаг входящего урона после смерти предыдущей цели
не запускает следующий бой. Урон завершённого боя не переносится на первое
наблюдение после него. Логи показывают HP/MP при начале боя и восстановлении,
пороги отдыха, а при новом уроне — изменение HP/CP и текущий MP.

Для фарма воина переход положительного HP цели в два свежих нулевых кадра
учитывается как убийство даже без распознанного имени («цель без имени»).
Исчезновение цели убийством не считается. Известное убийство не учитывается дважды
фоновым наблюдением и боевым циклом. Счётчик обновляется до подбора лута.
Для обучения урона по виду монстра и выбора через /target всё ещё нужна область имени.
# Pico CDC и общая область имени цели (2026-10-14)

При дроблении CDC-ответа приложение дочитывает ту же строку до общего timeout
250 мс. Команда не отправляется повторно. ERR, чужая sequence и незавершённая
строка останавливают ввод; watchdog платы остаётся прежним.

Имя монстра и ник игрока читаются из общей области над HP цели.
В ручной разметке статов есть отдельный режим «Имя цели над HP».
При автопоиске однострочное имя над найденным HP также предлагается для проверки.
Ранее выбранная область ника/класса/клана теперь сохраняется как общая панель цели.
Числовые HP могут оставаться отдельной областью ниже имени.
# Отдых воина по HP (2026-10-14)

`hp_rest_threshold 0.30` запускает отдых при собственном HP строго ниже 30%.
Перед каждым next target проверяется собственное HP. Ниже 30% персонаж ждёт
2,5 секунды (`quiet_seconds 2.5`), проверяя HP/CP. Допустим диапазон 1–10 секунд.
При входящем уроне выбирается
следующая цель и добивается агрессор; без урона начинается отдых.
после чего нажимается настроенная клавиша `rest`. Просто выделенная живая цель
без входящего урона отдых не блокирует. При новом уроне игра сама поднимает
персонажа: клавиша rest повторно не нажимается, сразу выбирается следующая цель
и добивается агрессор.
`hp_resume 0.90` задаёт HP для завершения отдыха; это отдельный порог от `hp_threshold`,
который управляет лечением скиллом. Отдых, запрошенный при HP <30%, не отменяется
одним хилом до 40%. Восстановление MP до `mp_resume` требуется только если MP
опустилось ниже `mp_threshold`. Ограничение `rest_timeout` сохраняется.
# Общая база монстров и подтверждения OCR (2026-10-14)

Во всех сценариях используется одна локальная SQLite-база:
`%LOCALAPPDATA%\HIDPilot\monsters.sqlite3`. В каждой новой зоне фоновый OCR
продолжает читать выбранных монстров. Два одинаковых свежих чтения позволяют
сверить имя с общей базой; для нового имени нужны три совпадающих чтения.
Сравнение игнорирует регистр и лишние пробелы, но не угадывает похожие названия.
Игроки, NPC, слабые и устаревшие результаты не попадают в базу.

Каждое подтверждение требует отдельного запуска OCR на новом кадре:
повтор результата из кеша или той же временной метки голосом не считается.
Учитываются последние 12 достоверных чтений за 30 секунд: три совпадения
при доле не менее 70% позволяют принять новое имя. Единичный сбой не стирает
подтверждения; равномерно смешанные имена не принимаются. Имя и распознанный уровень автоматически
сохраняются; база загружается при следующем запуске. В панели виден исходный OCR
и счётчик подтверждений до принятия имени. База ограничена 4096 именами.

Для /target используются имена, подтверждённые в текущем запуске фарма;
общая база служит справочником для сверки, а не списком целей всей карты.
Старые файлы баз рядом со сценариями не удаляются и автоматически не импортируются:
их прежние записи не проходили шесть независимых подтверждений.
# Перепроверка недобитой цели (2026-10-15)

Один пропуск HP больше не завершает бой. `target_verify_seconds 2` задаёт окно
перепроверки текущей цели без next target и дополнительных атакующих нажатий.
Живое HP возобновляет текущий бой; разрыв не используется как один большой удар
при обучении урона и не считается временем застревания.

Смерть подтверждается двумя последовательными свежими нулями. Нулевые значения
не кешируются числовым OCR: второе чтение проходит распознавание заново.
Живое HP после первого нуля отменяет предположение о смерти; пропуск между нулями
требует двух новых нулей. Подмена известной цели не подтверждает смерть предыдущей.
Если HP не удалось прочитать за отведённое время, убийство и лут не засчитываются,
скрипт переходит к повторному выбору цели. Входящий урон отмечается как признак
продолжающегося боя, но не доказывает состояние конкретного моба при нескольких агрессорах.
# Overhit без имени и устойчивые имена OCR (2026-10-15)

Положительные разницы HP между соседними свежими кадрами обычной атаки собираются
с первого боя независимо от распознавания имени. Для безымянной цели оценка
относится только к текущему бою и сбрасывается при выборе нового моба; данные
разных неизвестных видов не смешиваются. После трёх убийств оценка используется
для адаптивного добивания. Нулевой остаток, длинные разрывы OCR и урон после
дополнительного скилла по-прежнему не включаются в средний обычный удар.

`overhit_hp_threshold 0.02` разрешает добивание при HP до 2% уже с первого моба,
даже без имени и оценки урона. Настройки `overhit_keys` и интервал повторения сохраняются.
Изменение HP между кадрами является приблизительной оценкой: за один интервал
могут пройти несколько атак или входящий урон от сопартийцев.

Для узкой области имени OCR пробует исходный фрагмент и очищенные светлые буквы
с увеличением x3, без поиска текстовых блоков. При неудаче остаётся обычный detector OCR.
Подтверждение базы использует независимые чтения в окне 30 секунд вместо строгой
последовательности без единого пропуска. Новое имя требует шести совпадений и
70% голосов среди последних 12 достоверных чтений; известное — двух и той же доли.
# Подъём после отдыха и удержание overhit (2026-10-15)

`stand -` задаёт отдельную клавишу подъёма после обычного восстановления.
При нападении игра поднимает персонажа сама, поэтому дополнительного подъёма нет.
`overhit_hold_ms 700` удерживает overhit 0,7 секунды; обычные атаки сохраняют
короткое нажатие. `overhit_early_chance 0.50` даёт одну попытку на бой нажать
overhit на один средний удар раньше: после предполагаемого следующего обычного
удара HP должно попасть в обычный порог добивания. Решение случайное один раз,
повторные кадры его не переигрывают. Откаты скиллов сохраняются; без оценки
урона упреждение не применяется, а добивание при HP до 2% остаётся доступным.

# Циклы поиска и время фарма в часах (2026-10-15)

В мили-фарме `attack_delay 1.5` задаёт повтор кнопки атаки по живой цели
каждые 1,5 секунды. Лечение и дополнительные скиллы выполняются первыми;
после них расписание атаки возобновляется без серии пропущенных нажатий.
Повтор атаки не продлевает время сближения или таймаут отсутствия урона.

Если пять неудачных боёв подряд заканчиваются без снижения HP цели с одним
подтверждённым именем, запускается выход из застревания. Скрипт случайно выбирает
W/A либо S/D и нажимает клавиши попеременно по 1,5 секунды, всего 20–30 нажатий.
Это эвристика по имени: отдельные мобы одного типа визуально не идентифицируются.
Успешный урон сбрасывает счётчик; неизвестное имя не считается подтверждённым повтором.

После каждого удержания проверяются своё HP и next target. При падении своего HP
бег прекращается, а выбранная через next target живая цель передаётся в бой.
Другая цель с подтверждённым именем также прекращает выход и сразу атакуется.
Мёртвые, неизвестные по имени цели, известные игроки и NPC не подтверждают
успешный выбор другой цели. Если первый проход не помог, нажимается клавиша
сесть/встать `rest` и выполняется второй проход с теми же ранними остановками.
После двух безуспешных проходов возобновляется обычный поиск. Пауза отменяет
текущий выход; STOP и общий лимит сессии сохраняются.

`search_cycles 30` задаёт число полных циклов поиска, минимум 1, по умолчанию 30.
Каждый цикл повторяет next target и случайные пробежки WASD (до `search_moves`,
по умолчанию 3), затем перебирает известные текущей сессии имена через /target.
При найденной цели поиск сразу завершается; после всех неудачных циклов фарм останавливается.
После каждого `/target` достаточно распознанного положительного HP выбранной цели:
ожидание точного OCR-имени не требуется. Известные игроки и NPC исключаются.
Оставшиеся имена не вводятся — сразу запускается атака для сближения.
Проверка собственного HP перед выбором цели сохраняется.

`max_hours 3` задаёт лимит фарма в часах; дробные значения разрешены, например 1.5.
По умолчанию фарм ограничен тремя часами; внешний таймер учитывает заданные часы.
Старый `max_seconds` поддерживается для существующих сценариев. Указывайте одну
единицу времени: противоречащие друг другу часы и секунды отвергаются.
Число боевых циклов `cycles` задаётся отдельно от `search_cycles`.

# Лечение во время незавершённого боя (2026-10-15)

Низкое собственное HP и нажатие лечения не завершают бой. После лечения
проверяется новый кадр: при живом HP той же цели возобновляется обычная атака,
без next target и отдыха. Пауза лечения не участвует в оценке обычного удара.
Количество лечебных нажатий за бой ограничено `heal_attempts`; после этого
продолжается добивание, общий `combat_timeout` сохраняется.
Если лечение сменило цель или HP пропало, смерть не засчитывается и лут
не отправляется. В логе отдельно отображаются лечение, возобновление атаки
и подтверждённая смерть.
