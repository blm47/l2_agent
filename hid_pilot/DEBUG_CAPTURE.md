# Сбор кадров для отладки

Кнопка **ДебагСтарт** рядом с START / PAUSE / STOP запускает фарм или дуо
с автоматическим сохранением ошибок наблюдения. Отдельная команда не требуется.
Обычный **START** не запускает запись кадров и не сохраняет снимки ошибок HP/MP.
Режим действует только на текущий запуск: следующий START снова обычный. Каталог:
`%LOCALAPPDATA%/HIDPilot/observation-debug/event-00` … `event-31`.
Путь также выводится в журнал при старте фарма.

Причины записи: потеря HP недавно живой цели, нулевое HP, маркер смерти,
нераспознанное имя живой цели, неизвестные уровни в настроенных ROI и ошибки
HP/MP. Событие содержит `before_*` и `failure_*`: предыдущий и проблемный кадры
окна с PNG-вырезками. `event.json` хранит время, причину, профиль, источники HP/MP
и результаты распознавания. Неизвестное состояние не объявляется смертью.
Для уровней, области которых не настроены, автоматическая запись не запускается.

При настроенной пати также сохраняются её значения, профиль, возраст фонового
OCR и вырезки всех восьми строк (`party_1_name.png`, `party_1_hp.png` и т.д.).
Отдельные причины событий: `party_missing`, `party_resources_unknown`,
`party_name_unknown`, а при размеченной иконке класса — `party_class_unknown`.
Пути содержат префиксы `before_` и `failure_`, как у остальных ROI.

Запись идёт в отдельном потоке без дополнительного OCR. Ошибки уровней/имени
сохраняются не чаще раза в 3 секунды на причину, переходы HP цели — раз в 0.25 с.
Хранится до 32 событий по 8 MiB, старые слоты перезаписываются; превышающий
8 MiB комплект пропускается с предупреждением. При разборе скопируйте архив
до следующей продолжительной сессии. Кадры, которые не были записаны до
включения автоматической диагностики, восстановить из текстового лога нельзя.

## Отдельный сбор непрерывной серии

Запускайте из каталога `hid_pilot` отдельным процессом рядом с приложением:

```powershell
..\.venv\Scripts\python.exe -m hid_pilot.debug_capture --title Sangry --profile "extensions/scripts/farmer-healer.duo/farmer/farm-bars.json" --seconds 180 --fps 5
```

Передавайте именно профиль, загруженный для МА в GUI. Если он сохранён в другом
месте, замените путь. Без `--profile` сохраняются только полные кадры; это полезно,
если области уровней ещё не размечены. Список окон и их HWND:

```powershell
..\.venv\Scripts\python.exe -m hid_pilot.debug_capture --list
```

После запуска вручную вернитесь в игру. Сборщик не активирует окно, не отправляет
ввод и не запускает OCR. Снимается только клиентская область выбранного окна,
пока оно активно. При переключении на саппорта или другое приложение возникает
пропуск в серии кадров. Свёрнутое окно не снимается. Закрытие окна, смена PID,
геометрии или несоответствие профиля останавливают сбор. Ctrl+C завершает запись.

Результат: `artifacts/debug-capture/<время запуска>/`. В каждой нумерованной папке
находятся полный кадр JPEG и PNG-вырезки всех настроенных числовых областей,
полос, имени, уровней и маркера смерти. PNG сохраняют исходные пиксели вырезок.
`session.json` хранит профиль и параметры окна, `frames.jsonl` — время каждого
кадра для сопоставления с логом. Поле `label` пока пустое: разметка смерти или
цифр должна подтверждаться вручную, а не ошибающимся OCR.

По умолчанию запись ограничена 180 секундами, 5 кадрами/с и 512 MiB.
`--max-mb` меняет лимит хранения, `--output` — каталог. Старые серии не удаляются:
лимит относится к одному запуску. Следите за свободным местом между запусками.
При достижении лимита следующий комплект не записывается частично.

Для разбора нужны несколько боёв: живой моб, последние проценты HP, смерть,
исчезновение панели и следующая цель. Желательно сохранить соответствующий лог.
Для уровней нужны разные значения игрока и цели, включая кадры с ошибками.

В редакторе разметки запас имени справа теперь составляет 100% исходной ширины
вместо 60%, с ограничением краем окна. Существующие сохранённые ROI не расширяются
повторно. Чтобы применить новый запас, выделите имя заново и сохраните профиль.
